# Требования по движку

---
## 1. Производительность
#### Описание:
В основе движка должен лежать подход плотного 
(cache-friendly) расположения игровых данных и 
производительной обработки этих данных с 
возможностью параллелизации. Четкое разделение 
на компоненты и игровые объекты. Реализация 
деревьев поиска объектов в пространстве.

#### Набор операций и требования к ним:
- получение, добавление и удаление компонента 
по id объекта `O(1) time`
- 

#### Мысли по реализации:
- разложение компонентов/свойств игровых объектов 
на массивы примитивов
- хранение данных компонентов в байт-массивах (или 
в ByteBuffer'ах)
- группировка игровых объектов по набору компонентов 
(ключом для такой коллекции является уникальный набор 
типов компонентов, например, использовать BitSet для 
хранения ключа)
- выделение памяти под компоненты чанками 
фиксированного размера (размер известен до рантайма, 
вынести в проперти)

## 2. Гибкость
#### Описание:
Типы игровых данных должно быть удобно 
модифицировать и добавлять.

## 3. Слабая связность
#### Описание:
Модули должны быть слабо связанны друг с другом 
и иметь возможность безболезненного 
расширения/модифицирования.

## 4. Удобство работы в редакторе
#### Описание:
Должен быть реализован простой редактор сцен с 
помощью собственной графической библиотеки на 
целевой графической платформе (например, OpenGL) 
с отзывчивым интерфейсом. Должно быть разделение 
на игровые объекты и их свойства. 

#### Опционально: 
- адаптивный курсор (магнитится к пересекающимся 
элементам интерфейса и принимает их форму)

#### Мысли по реализации:
- использование древовидной структуры графических 
компонентов с проверками на пересечение на 
плоскости (chain-of-responsibility + tree)

## 5. Мультиплатформенность
#### Описание:
Возможность собирать проект под различные 
платформы (Windows, Linux, Android?)
